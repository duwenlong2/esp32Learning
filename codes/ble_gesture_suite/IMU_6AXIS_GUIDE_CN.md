# 6轴姿态校准方案 V1.1（面向普通用户）

你提得很对：校准流程必须先保证用户能做对，而不是算法看起来完整。

这份 V1.1 的核心目标只有三个：

1. 校准步骤少。
2. 失败可自动识别。
3. 错误不落盘，不污染运行结果。

---

## 0. 先讲清楚：6轴传感器到底是什么

很多同学第一次接触 IMU，会以为“6轴=6个方向的位置”。

这不对。6轴不是位置传感器，而是**运动状态传感器**。

6轴由两部分组成：

1. 三轴加速度计：`ax, ay, az`
2. 三轴陀螺仪：`gx, gy, gz`

你可以把它理解成：

1. 加速度计告诉你“现在受力方向如何”（静止时主要看到重力方向）
2. 陀螺仪告诉你“现在转得有多快”（角速度）

它们都不是“直接给姿态角”的。姿态角是后续算法算出来的。

### 0.1 三轴加速度计在看什么

加速度计读到的是传感器坐标系下的比力（specific force）。

静止时：

1. 加速度主要来自重力
2. 模长接近 1g（工程里常写成 16384 count，具体看量程）

因此静止状态下，它非常适合拿来算：

1. 设备“倾斜到什么方向”（roll/pitch）
2. 设备是否静止（方差和模长是否稳定）

#### 0.1.1 用真实日志举例（非假设）

下面这条数据来自本机真实采集日志：

1. 文件：`C:\Users\qaz21\AppData\Local\GestureLab\records\20260423_181911_alignment.csv`
2. 时间：`2026-04-23T18:22:23.2979969+08:00`
3. 原始值：
	1. `ax = -5324`
	2. `ay = -15780`
	3. `az = -292`
	4. （同一帧 gyro：`gx=-16, gy=14, gz=4`，角速度很小，符合静止特征）

先看加速度模长：

1. `|a| = sqrt(ax^2 + ay^2 + az^2)`
2. `|a| = sqrt((-5324)^2 + (-15780)^2 + (-292)^2) = 16656.49`
3. `|a| / 16384 = 1.0166 g`

解释：

1. 这个值非常接近 1g，说明该帧主要反映的是重力方向
2. 可用于姿态估计与静止质量判断

再看姿态角（V1 常用公式）：

1. `roll = atan2(ay, az)`
2. `pitch = atan2(-ax, sqrt(ay^2 + az^2))`

代入后：

1. `roll = -91.06 deg`
2. `pitch = 18.64 deg`

这表示：

1. 设备当时明显处于“侧向倾斜”姿态（接近横向立起）
2. 同时有约 18.6 度的前后俯仰分量

这就是三轴加速度计在静止状态下最重要的价值：

1. 不需要运动就能给出重力方向
2. 进而可稳定估计 roll/pitch
3. 还能用模长是否接近 1g 来判断样本是否可用于校准

### 0.2 三轴陀螺仪在看什么

陀螺仪读的是角速度：

1. `gx`：绕传感器 X 轴的旋转速度
2. `gy`：绕传感器 Y 轴的旋转速度
3. `gz`：绕传感器 Z 轴的旋转速度

它擅长捕捉“瞬时动作”，比如抬手突然启动、突然停止。

它不擅长单独长期积分姿态，因为会漂移（bias 导致积分误差累积）。

## 0.3 数学模型（小白版 + 工程版）

先看小白版：

1. 传感器读数 = 真值 + 偏差 + 噪声

工程版写法：

1. `a_meas = S_a * R_a * a_true + b_a + n_a`
2. `w_meas = S_g * R_g * w_true + b_g + n_g`

各符号含义：

1. `S`：尺度误差（放大倍数不准）
2. `R`：轴不正交/安装误差
3. `b`：偏置（零点漂移）
4. `n`：噪声

V1.1 先重点解决两件最影响体验的事：

1. `gyro bias`（静止时估计并扣除）
2. `axis map + sign`（把设备轴和显示轴对齐）

这是“先能用，再做高级外参”的策略。

---

## 0.4 为什么常说 6轴姿态是“2.5D”

结论先说：

1. roll 可用
2. pitch 可用
3. yaw 绝对值不可直接观测（没有磁力计时）

原因（数学直觉）：

1. 加速度计在静止时只看到重力方向 `g`
2. 你绕重力方向旋转（也就是 yaw 变化）时，`g` 在传感器里几乎不变
3. 所以仅靠加速度计无法知道“朝向北东南西”的绝对角

这不是算法偷懒，是可观测性边界。

所以当前 V1.1 的设计是合理的：

1. 先把 roll/pitch 做稳
2. 用 gyro 强度做动作判定
3. yaw 先不作为核心触发依据

---

## 0.5 你当前流程中 6轴数据分别承担什么角色

在这份方案里，6轴数据是分工明确的：

1. `ax/ay/az`：
	1. 估计重力方向
	2. 计算 roll/pitch
	3. 判断静止质量
2. `gx/gy/gz`：
	1. 估计 gyro bias
	2. 计算动作强度（如 `gyroMagnitude`）
	3. 用于状态机阈值（启动、稳定、打断）

这就是为什么文档里会同时有“姿态窗口阈值”和“陀螺阈值”：

1. 姿态窗口保证方向正确
2. 陀螺阈值保证动作节奏正确

两者缺一不可。

---

## 0.6 快速校准两步在数学上到底做了什么

Step A（平放静止）本质是：

1. 用静止窗口估计 `gyro bias`
2. 记录基准重力向量 `g0`
3. 评估样本质量（方差、模长、抖动）

Step B（抬起并保持）本质是：

1. 记录目标姿态重力向量 `g1`
2. 比较 `g0` 和 `g1` 得到主安装方向变化
3. 输出可解释的 `axis map + sign`

这比一上来做全量四元数外参更稳，因为：

1. 用户容易做对
2. 失败容易解释
3. 质量门控简单明确

---

## 0.7 常见误区（必须先统一）

1. 误区：6轴能直接给绝对朝向 yaw
	1. 纠正：6轴可给相对变化，绝对 yaw 需要额外参考（如磁力计）
2. 误区：做动作越快越好
	1. 纠正：校准时慢而稳更好，快动作会让线性加速度污染重力估计
3. 误区：高级 L/R/F/B/U/D 是“空间平移”
	1. 纠正：应是原地小角度旋转，尽量不移动中心

---

## 0.8 为什么 V1.1 先用 axis map + sign，不直接上四元数外参

因为当前阶段目标是“用户做得对 + 系统不误判”。

axis map + sign 的优势：

1. 可解释：一眼能看懂“viewerX <- -sensorY”
2. 可回退：结果差就拒绝覆盖旧 profile
3. 可分步：后续平滑升级到四元数外参，不推翻当前流程

这也是 V1.1 里“先实用、再高级”的核心决策。

---

## 1. 设计原则

1. 默认只给“快速校准”，两步完成。
2. 高级校准（L/R/F/B/U/D）放到可选，不强迫普通用户。
3. 每步都做质量门控，不合格就明确提示重试。
4. profile 有版本和置信度，不可信就拒绝应用。

---

## 2. 用户流程（快速校准）

## Step A：平放静止（2 秒）

- 引导文案：把设备自然放稳，不要触碰。
- 系统动作：
- 估计 gyro bias。
- 记录当前重力方向 g0。
- 计算静止质量分数（陀螺抖动、加速度方差）。

如果质量不达标：

- 不保存。
- 弹出明确原因：例如“设备在抖动，请重试”。

## Step B：抬起并保持（2 秒）

- 引导文案：按正常使用姿态拿起并保持不动。
- 系统动作：
- 记录重力方向 g1。
- 计算从 g0 到 g1 的安装旋转主分量。
- 与 Step A 一起求得 V1 映射参数。

如果质量不达标：

- 不保存。
- 提示“动作太快/晃动过大，请慢一点再做一次”。

---

## 3. 用户流程（高级校准，可选）

仅当快速校准失败多次，或安装姿态很复杂时，才进入高级模式。

这里的核心要求只有一条：

- 做“原地转动”，不要做“空间位移”。

也就是说：

- 设备拿在手里可以。
- 手腕转动可以。
- 设备中心尽量停在胸前一个小范围内。
- 不要把整个手臂往左甩、往右甩、往前送、往后拉。

高级模式里，L/R/F/B/U/D 不是“把设备移到左边/右边/前面/后面/上面/下面”，而是“围绕设备中间，做一个小角度定向旋转”。

高级步骤：

1. Start Record
2. 依次动作并点标记：L, R, F, B, U, D
3. Stop Record

建议实际执行时使用“分组采集”以降低失败率：

1. 一份日志只做 `L/R`
2. 一份日志只做 `F/B`
3. 一份日志只做 `U/D`

采完后用脚本做汇总（可一次传多份）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\analyze_pair_mapping.ps1 \
	-CsvPathList "C:\Users\<you>\AppData\Local\GestureLab\records\lr.csv;C:\Users\<you>\AppData\Local\GestureLab\records\fb.csv;C:\Users\<you>\AppData\Local\GestureLab\records\ud.csv"
```

脚本会输出：

- 每份日志的单点增量与配对质量
- 跨日志“每一组取最好结果”的汇总表
- 每组方向结论（例如 `L=+X, R=-X`）

### 3.1 手持采集时，动作到底怎么做

默认姿态：

- 人站着或坐着都可以。
- 上臂尽量别动，手肘自然靠近身体。
- 设备拿在胸前，离身体约 20 到 30 cm。
- 先保持静止 1 秒，再做动作。

动作幅度：

- 每次只转一个小角度，建议 20 到 35 度。
- 转过去后停住 1 秒，再回到中间。
- 不要求快，慢一点更好。

什么叫 L / R：

- 这组不要再理解成“朝向左拧 / 朝向右拧”。
- 对 6 轴方案来说，纯粹的左右转头式偏航，在静止前后几乎不改变重力方向，不适合拿来做当前这版配对分析。
- 这组现在改成“左歪 / 右歪”，也就是左右横滚。
- 设备仍拿在胸前，中心尽量不移动。
- 让设备左侧抬高、右侧压低一点，停住，记 `L`。
- 回中。
- 再让设备右侧抬高、左侧压低一点，停住，记 `R`。

更直白一点：

- 不是把设备朝左边拧一点、朝右边拧一点。
- 是像端着一块小板子那样，让它向左歪一点、向右歪一点。

什么叫 U / D：

- 为了避免和 `F/B` 命名冲突，V1.1 中把 `U/D` 定义为“可选复核组”，不是主映射组。
- 如果你要采 `U/D`，动作可以与 `F/B` 相同（上抬 / 下压），但它只用于重复性检查，不参与最终轴映射决策。
- 换句话说：当前最终映射以 `L/R` + `F/B` 为准，`U/D` 只做质量复核。

什么叫 F / B：

- 这组定义为“前倾 / 后仰”（主映射组）。
- 设备仍在胸前，中心尽量不移动。
- 让设备顶部向前扣一点，停住，记 `F`。
- 回中。
- 再让设备顶部向后仰一点，停住，记 `B`。

### 3.2 现在先只做一组：L / R

为了先调出一个正常的基准，第一轮只采 `L / R`。

操作顺序：

1. Start Record
2. 静止 1 秒
3. 设备向左歪 20 到 35 度，停住，点 `L`
4. 回到中间，静止 1 秒
5. 设备向右歪 20 到 35 度，停住，点 `R`
6. 回到中间，静止 1 秒
7. Stop Record

如果动作做对了，脚本应该看到：

- `L` 和 `R` 主要落在同一个轴上
- 两者符号相反
- 这一组的一致性明显上升

### 3.3 这几种动作都算错

- 整个手臂向左平移、向右平移
- 往前戳、往后拉
- 一边转一边移动位置
- 标记刚点下去就继续晃动
- 每次转的不是同一种动作

系统会自动做成对一致性检查：

- L 与 R 是否反向
- F 与 B 是否反向
- U 与 D 是否反向

任何一组不合格，只让用户重做那一组，不重做全流程。

## 4. 算法输出（V1.1）

V1.1 先输出 axis map + sign（足够实用、好解释、好排错）。

输出内容：

- viewerX <- sensorAxis + sign
- viewerY <- sensorAxis + sign
- viewerZ <- sensorAxis + sign
- confidence: xScore, yScore, zScore, totalScore

示例：

- viewerX = -sensorX
- viewerY = +sensorY
- viewerZ = +sensorZ

说明：

- 四元数外参留到 V2，不阻塞当前上线。

---

## 5. profile 文件建议

建议字段：

- profileVersion
- createdAt
- sourceMode: quick 或 advanced
- gyroBias
- axisMap
- confidence
- valid

应用规则：

1. valid=false 时不允许应用。
2. totalScore 低于阈值时不允许覆盖旧 profile。
3. 总是保留最后一个可用 profile 作为回退。

---

## 6. 运行时顺序

每帧按以下顺序：

1. 读取 raw imu: ax, ay, az, gx, gy, gz
2. 扣 gyro bias
3. 应用 axisMap + sign
4. 计算 roll/pitch（V1）
5. 输出到 Three.js

注意：

- 运行时禁止手调符号。
- 所有变更必须来自新的校准 profile。

---

## 7. 验收标准（用户视角）

快速校准算通过的条件：

1. 用户 30 秒内可完成。
2. 不看说明也能完成一次。
3. 失败时有明确提示且可重试。
4. 通过后模型方向不再明显反向。

高级校准算通过的条件：

1. 六个方向全部打标。
2. 至少 5/6 方向通过一致性检查。
3. 结果优于快速校准（totalScore 更高）。
