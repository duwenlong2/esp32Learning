# 6轴姿态校准方案 V1.1（面向普通用户）

你提得很对：校准流程必须先保证用户能做对，而不是算法看起来完整。

这份 V1.1 的核心目标只有三个：

1. 校准步骤少。
2. 失败可自动识别。
3. 错误不落盘，不污染运行结果。

---

## 1. 设计原则

1. 默认只给“快速校准”，两步完成。
2. 高级校准（L/R/F/B/U/D）放到可选，不强迫普通用户。
3. 每步都做质量门控，不合格就明确提示重试。
4. profile 有版本和置信度，不可信就拒绝应用。

---

## 2. 用户流程（快速校准）

## Step A：平放静止（2 秒）

- 引导文案：把设备自然放稳，不要触碰。
- 系统动作：
- 估计 gyro bias。
- 记录当前重力方向 g0。
- 计算静止质量分数（陀螺抖动、加速度方差）。

如果质量不达标：

- 不保存。
- 弹出明确原因：例如“设备在抖动，请重试”。

## Step B：抬起并保持（2 秒）

- 引导文案：按正常使用姿态拿起并保持不动。
- 系统动作：
- 记录重力方向 g1。
- 计算从 g0 到 g1 的安装旋转主分量。
- 与 Step A 一起求得 V1 映射参数。

如果质量不达标：

- 不保存。
- 提示“动作太快/晃动过大，请慢一点再做一次”。

---

## 3. 用户流程（高级校准，可选）

仅当快速校准失败多次，或安装姿态很复杂时，才进入高级模式。

这里的核心要求只有一条：

- 做“原地转动”，不要做“空间位移”。

也就是说：

- 设备拿在手里可以。
- 手腕转动可以。
- 设备中心尽量停在胸前一个小范围内。
- 不要把整个手臂往左甩、往右甩、往前送、往后拉。

高级模式里，L/R/F/B/U/D 不是“把设备移到左边/右边/前面/后面/上面/下面”，而是“围绕设备中间，做一个小角度定向旋转”。

高级步骤：

1. Start Record
2. 依次动作并点标记：L, R, F, B, U, D
3. Stop Record

建议实际执行时使用“分组采集”以降低失败率：

1. 一份日志只做 `L/R`
2. 一份日志只做 `F/B`
3. 一份日志只做 `U/D`

采完后用脚本做汇总（可一次传多份）：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\analyze_pair_mapping.ps1 \
	-CsvPathList "C:\Users\<you>\AppData\Local\GestureLab\records\lr.csv;C:\Users\<you>\AppData\Local\GestureLab\records\fb.csv;C:\Users\<you>\AppData\Local\GestureLab\records\ud.csv"
```

脚本会输出：

- 每份日志的单点增量与配对质量
- 跨日志“每一组取最好结果”的汇总表
- 每组方向结论（例如 `L=+X, R=-X`）

### 3.1 手持采集时，动作到底怎么做

默认姿态：

- 人站着或坐着都可以。
- 上臂尽量别动，手肘自然靠近身体。
- 设备拿在胸前，离身体约 20 到 30 cm。
- 先保持静止 1 秒，再做动作。

动作幅度：

- 每次只转一个小角度，建议 20 到 35 度。
- 转过去后停住 1 秒，再回到中间。
- 不要求快，慢一点更好。

什么叫 L / R：

- 这组不要再理解成“朝向左拧 / 朝向右拧”。
- 对 6 轴方案来说，纯粹的左右转头式偏航，在静止前后几乎不改变重力方向，不适合拿来做当前这版配对分析。
- 这组现在改成“左歪 / 右歪”，也就是左右横滚。
- 设备仍拿在胸前，中心尽量不移动。
- 让设备左侧抬高、右侧压低一点，停住，记 `L`。
- 回中。
- 再让设备右侧抬高、左侧压低一点，停住，记 `R`。

更直白一点：

- 不是把设备朝左边拧一点、朝右边拧一点。
- 是像端着一块小板子那样，让它向左歪一点、向右歪一点。

什么叫 U / D：

- 为了避免和 `F/B` 命名冲突，V1.1 中把 `U/D` 定义为“可选复核组”，不是主映射组。
- 如果你要采 `U/D`，动作可以与 `F/B` 相同（上抬 / 下压），但它只用于重复性检查，不参与最终轴映射决策。
- 换句话说：当前最终映射以 `L/R` + `F/B` 为准，`U/D` 只做质量复核。

什么叫 F / B：

- 这组定义为“前倾 / 后仰”（主映射组）。
- 设备仍在胸前，中心尽量不移动。
- 让设备顶部向前扣一点，停住，记 `F`。
- 回中。
- 再让设备顶部向后仰一点，停住，记 `B`。

### 3.2 现在先只做一组：L / R

为了先调出一个正常的基准，第一轮只采 `L / R`。

操作顺序：

1. Start Record
2. 静止 1 秒
3. 设备向左歪 20 到 35 度，停住，点 `L`
4. 回到中间，静止 1 秒
5. 设备向右歪 20 到 35 度，停住，点 `R`
6. 回到中间，静止 1 秒
7. Stop Record

如果动作做对了，脚本应该看到：

- `L` 和 `R` 主要落在同一个轴上
- 两者符号相反
- 这一组的一致性明显上升

### 3.3 这几种动作都算错

- 整个手臂向左平移、向右平移
- 往前戳、往后拉
- 一边转一边移动位置
- 标记刚点下去就继续晃动
- 每次转的不是同一种动作

系统会自动做成对一致性检查：

- L 与 R 是否反向
- F 与 B 是否反向
- U 与 D 是否反向

任何一组不合格，只让用户重做那一组，不重做全流程。

## 4. 算法输出（V1.1）

V1.1 先输出 axis map + sign（足够实用、好解释、好排错）。

输出内容：

- viewerX <- sensorAxis + sign
- viewerY <- sensorAxis + sign
- viewerZ <- sensorAxis + sign
- confidence: xScore, yScore, zScore, totalScore

示例：

- viewerX = -sensorX
- viewerY = +sensorY
- viewerZ = +sensorZ

说明：

- 四元数外参留到 V2，不阻塞当前上线。

---

## 5. profile 文件建议

建议字段：

- profileVersion
- createdAt
- sourceMode: quick 或 advanced
- gyroBias
- axisMap
- confidence
- valid

应用规则：

1. valid=false 时不允许应用。
2. totalScore 低于阈值时不允许覆盖旧 profile。
3. 总是保留最后一个可用 profile 作为回退。

---

## 6. 运行时顺序

每帧按以下顺序：

1. 读取 raw imu: ax, ay, az, gx, gy, gz
2. 扣 gyro bias
3. 应用 axisMap + sign
4. 计算 roll/pitch（V1）
5. 输出到 Three.js

注意：

- 运行时禁止手调符号。
- 所有变更必须来自新的校准 profile。

---

## 7. 验收标准（用户视角）

快速校准算通过的条件：

1. 用户 30 秒内可完成。
2. 不看说明也能完成一次。
3. 失败时有明确提示且可重试。
4. 通过后模型方向不再明显反向。

高级校准算通过的条件：

1. 六个方向全部打标。
2. 至少 5/6 方向通过一致性检查。
3. 结果优于快速校准（totalScore 更高）。

---

## 8. V2 计划（后续）

在 V1.1 稳定后升级：

1. 用四元数安装外参替代 axis map + sign。
2. 加入静止检测下的在线 bias 更新。
3. 接入 Mahony/Madgwick 融合，提升动态表现。
4. 做“自动分组重采”与“质量热力图”。

---

## 9. 当前决策

先上 V1.1。

理由：

- 用户成功率高。
- 研发实现成本可控。
- 后续可平滑升级到四元数外参，不推翻现有流程。
